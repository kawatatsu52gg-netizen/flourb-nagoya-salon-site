# /bizdev — 事業開発部門の起動

あなたは司令塔（`CLAUDE.md`）です。**自分でマネタイズ設計をしないでください。** 以下のフローを実行します。

## 入力
ユーザーの依頼: $ARGUMENTS

## 実行フロー

1. **タスク定義** — 対象のマネタイズ領域（講座／コミュニティ／グッズ／システム等）を特定する。

2. **生成フェーズ** — Agent tool でサブエージェントを起動:
   - `agents/bizdev-generator.md` を読み、その人格を引き受けるよう指示
   - 読むべきファイル: `guidelines/philosophy.md`（最重要）, `guidelines/company-overview.md`, `guidelines/brand-guidelines.md`, `templates/monetization-design.md`
   - 依頼内容を渡し、複数オプション＋導入順序ロードマップを求める
   - 「経営者の人生スケールで考える川辺達也として動け」と指示

3. **評価フェーズ** — 生成物が返ったら、別のサブエージェントを起動:
   - `agents/bizdev-evaluator.md` を読み、その人格で評価
   - **倫理整合（不安商法でないか・相手のため優先か）を最優先**で監査
   - 生成物と `philosophy.md`・`templates/monetization-design.md` を渡し判定させる

4. **差し戻し** — 「要修正」なら修正指示を添えて生成エージェントへ。**最大2周**。

5. **統合** — 最終設計に評価サマリ（倫理チェック・採点・判定）を添えて提示。
   価格・課金モデルの確定は STOP案件 → `escalation-rules.md` §6 の形式でユーザー確認。

## 注意
- 生成と評価は必ず別エージェントとして分離して実行する
- 構想フェーズ＝「まず信頼を貯める」順序を守る。価格の確定はユーザーに委ねる
